Hardware Security & Libreboot

Aegis OS · hardening your machine below the operating system

Aegis protects what happens inside the running system. But an attacker with physical access — or a backdoor in the firmware — sits below it. This guide covers maximising hardware security: free firmware (Libreboot/coreboot), neutralising the Intel ME / AMD PSP, boot integrity, IOMMU/DMA protection, radios and sensors, and defending against cold-boot and "evil-maid" attacks.

1. What this defends against

Aegis is amnesic and routes everything through Tor, so it is strong against remote and post-mortem analysis. Hardware hardening adds defence against:

  • Firmware backdoors / implants — proprietary BIOS, Intel ME, AMD PSP run below the OS with full memory access and their own network paths.
  • Evil-maid attacks — someone with brief physical access tampering with your bootloader or firmware while you're away.
  • DMA attacks — malicious Thunderbolt/PCIe/USB devices reading RAM directly.
  • Cold-boot attacks — recovering keys from RAM after power-off.

Tier 1 — everyone

Firmware password, boot order locked, disable unused radios, full-disk encryption, use the amnesic live session.

Tier 2 — serious

Measured boot / TPM, IOMMU on, USBGuard, the "maximum CPU mitigations" boot entry, tamper-evidence (glitter nail polish on screws).

Tier 3 — maximal

Libreboot/coreboot with a neutralised ME/PSP, a supported laptop (e.g. ThinkPad X230/T440p), external SPI flashing, Heads firmware.

2. Libreboot & coreboot

Libreboot is a free/libre boot firmware (a coreboot distribution) that replaces your proprietary BIOS/UEFI. It removes a huge amount of closed, unauditable code that runs before your OS — and on supported machines it ships with the Intel ME already disabled/neutralised.

Flashing firmware can brick your machine. A failed flash may need an external SPI programmer (e.g. a CH341A clip) to recover. Read your exact board's page end to end first, and have a recovery plan. Do this on a machine you can afford to lose.

Is my machine supported?

Check the hardware list at libreboot.org/docs/hardware. Classic well-supported targets: ThinkPad X200/X230/T400/T440p, some desktops. Modern laptops with Boot Guard fused on generally cannot run coreboot/Libreboot.

Rough process

  • Confirm the exact model/variant and flash chip.
  • Back up your current firmware (ideally twice) with flashrom before writing.
  • Internal flashing where supported; otherwise external SPI with a clip.
  • Consider Heads on top for TPM-measured, tamper-evident boot.

Full instructions: libreboot.org/docs/install · coreboot: coreboot.org.

3. Intel ME / AMD PSP

The Intel Management Engine (and AMD's PSP) is a separate processor inside your chipset that runs signed, proprietary code with access to memory and the network, even when the machine is "off". You cannot fully remove it, but on many platforms you can neutralise most of it.

  • Libreboot/coreboot builds can run me_cleaner to strip the ME to a minimal stub (github.com/corna/me_cleaner).
  • Prefer hardware old enough to survive ME neutralisation (Sandy/Ivy Bridge era) if this is a priority.
  • On AMD, PSP removal is far less mature — treat it as not solved.

4. Boot integrity — Secure Boot, Measured Boot, TPM

Goal: detect or prevent tampering with the firmware/bootloader (evil-maid).

  • Measured boot + TPM is stronger than Secure Boot for this: the firmware hashes each stage into TPM PCRs; a changed bootloader changes the measurement and the TPM refuses to release your secret (or shows a different value). Heads implements this with a visible verification.
  • Secure Boot (UEFI) blocks unsigned bootloaders. Useful, but you must enrol your own keys to get real benefit, and it doesn't protect against a firmware-level implant.
  • Check TPM presence: ls /sys/class/tpm. Inspect PCRs with tpm2_pcrread.

5. Firmware / BIOS passwords

  • Set a supervisor/admin firmware password and lock the boot order to internal media only.
  • Disable booting from USB/network in firmware when you're not installing.
  • Know the limits: on many laptops the password can be reset by clearing the CMOS/EC or reading an EEPROM — it deters casual access, not a determined attacker with the machine open. Libreboot + a GRUB password + measured boot is the stronger story.

6. IOMMU & DMA protection

A malicious Thunderbolt/PCIe/ExpressCard/FireWire device can read and write RAM directly unless the IOMMU confines it. Aegis already boots with intel_iommu=on amd_iommu=on efi=disable_early_pci_dma.

  • Verify: dmesg | grep -i -e DMAR -e IOMMU should show the IOMMU enabled.
  • Prefer machines without Thunderbolt, or disable Thunderbolt/"security level" in firmware.
  • Aegis ships USBGuard — authorise only the USB devices you expect, block the rest.

7. Radios, camera & microphone

  • Kill radios you aren't using: rfkill block wifi bluetooth (Aegis includes rfkill).
  • For real guarantees, remove/disable the Wi-Fi/BT card, use a hardware kill switch, or a Faraday pouch.
  • Camera/mic: a physical shutter/tape for the camera; unplug or physically disable internal mics where you can. Software muting is not a guarantee.
  • MAC address: Aegis randomises it per connection (see the Control Center), so the hardware address isn't broadcast.

8. Cold-boot & evil-maid

  • Cold-boot: encryption keys live in RAM while running. Aegis wipes RAM on shutdown (aegis-ramwipe) and boots with init_on_free=1 page_poison=1. Prefer a full shutdown over suspend; soldered RAM is harder to transplant than DIMMs.
  • Evil-maid: combine measured boot (Heads) with physical tamper-evidence — unique glitter nail polish over the case screws, photographed; tamper-evident seals; keep the machine with you.

9. CPU mitigations (RETBleed &c.)

Aegis boots by default with mitigations=auto,nosmt, which enables the appropriate speculative-execution mitigations (RETBleed included) and disables SMT/Hyper-Threading.

For the strongest tier, choose “Aegis OS (maximum CPU mitigations)” from the boot menu. It forces mitigations=full,nosmt retbleed=auto spec_rstack_overflow=safe-ret gather_data_sampling=force l1tf=full,force. This costs performance — use it on shared or high-risk hardware.

Check what's active: cat /proc/cmdline and grep . /sys/devices/system/cpu/vulnerabilities/*.

10. Firewall note — gufw / ufw

Aegis ships gufw and ufw because they're familiar, but ufw is left disabled on purpose. Aegis's own fail-closed nftables firewall forces every packet through Tor. Enabling ufw flushes and replaces that ruleset, which can break the Tor anonymity guarantee and leak traffic. Manage the firewall through the Aegis Control Center. Only enable ufw if you understand you are taking over from the fail-closed firewall.

11. Quick checklist

  • ☑ Firmware supervisor password set; boot locked to internal disk.
  • ☑ Unused radios off (rfkill); camera shutter on.
  • ☑ IOMMU verified; USBGuard authorising only known devices.
  • ☑ Full shutdown (RAM wiped), not suspend, when leaving the machine.
  • ☑ Tamper-evidence on the case; machine kept with you.
  • ☑ Consider Libreboot/coreboot + me_cleaner + Heads on supported hardware.
  • ☑ Use the "maximum CPU mitigations" boot entry on high-risk hardware.
